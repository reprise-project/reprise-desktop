# Translations

Reprise's UI strings are [Fluent](https://projectfluent.org/) messages. Each
crate compiles its English strings in, so a program always has every string;
other languages are `.ftl` files loaded at start.

## Where strings live

| What | Where |
| --- | --- |
| A crate's English strings | `crates/<crate>/locale/en.ftl`, compiled in |
| A translation in the tree | `data/locale/<lang>/<domain>.ftl` |
| Installed translations | `/usr/share/reprise/locale/<lang>/<domain>.ftl` |
| Your own translations | `~/.local/share/reprise/locale/<lang>/<domain>.ftl` |

The domain is the name a crate gives `reprisekit::strings!`: `reprisekit`,
`repriseapp`, `notepad`, `about`. `<lang>` is a language tag such as `de`,
`pt-BR` or `pt_BR`.

Translations are looked up in `$XDG_DATA_HOME/reprise/locale` (default
`~/.local/share/reprise/locale`), then in `reprise/locale` under each
`$XDG_DATA_DIRS` entry (default `/usr/local/share:/usr/share`). The packages
install `data/locale` under `/usr/share/reprise/locale`.

## Which language

The languages asked for are, in order, `LANGUAGE` (a colon-separated list),
then the message locale: `LC_ALL`, else `LC_MESSAGES`, else `LANG`. A `C` or
`POSIX` locale means English and ignores `LANGUAGE`, as gettext does.
`fluent-langneg` matches that list against the installed languages, so
`de_AT.UTF-8` finds `de`.

Each domain loads its files once, on its first string. A program picks up a
new language when it restarts.

## Fallback

A domain is a chain of bundles: the negotiated languages in order, then the
compiled-in English. A string comes from the first bundle that has its id and
formats without an error, so a partial translation shows English for the rest
and a broken message falls back to English instead of showing a hole. An id
in no bundle shows as the id itself and logs a warning.

A file in your data dir sits ahead of the system copy of the same language,
so it can hold only the strings you want to change.

## Adding a string

1. Add the message to the crate's `locale/en.ftl`. Ids are kebab-case,
   grouped under `##` section comments.
2. Use it with `tr!`:

   ```rust
   use reprisekit::tr;

   let title = tr!("window-title", name = name.as_str());
   ```

   The id must be a literal. Arguments are `name = value` pairs; a value is
   anything `reprisekit::i18n::Value` converts from: `&str`, `String` or a
   number.
3. For the common buttons and the edit menu, use reprisekit's strings from
   any crate: `reprisekit::kit_tr!("ok")`, `"cancel"`, `"apply"`, `"close"`,
   `"yes"` and `"no"` (with access keys), `"yes-bare"` and `"no-bare"`
   (without).

A crate that has no strings yet adds `locale/en.ftl` and one line at its
root:

```rust
reprisekit::strings!("explorer");
```

### Access keys

An `&` in a string marks the next letter as its access key, as in code:
`menu-file = &File`. A translation keeps one `&`, on a letter of the
translated word, and should not give two items of one menu the same letter.
Text from outside (a file name, a device name) is escaped with
`reprisekit::text::escape_mnemonic` before it goes in as an argument.

### Numbers and plurals

A number argument is formatted in the UI language: digits are grouped and
the decimal separator is the language's. The separators are reprisekit's
`number-group-separator` and `number-decimal-separator` messages, so a
language sets them once in its `reprisekit.ftl`. Fraction digits come from
`NUMBER()`:

```
size-gb = { NUMBER($gb, minimumFractionDigits: 1, maximumFractionDigits: 1) } GB
```

Pass a number that must not be grouped (a line number, a resolution) as a
string: `line = n.to_string()`.

Plurals use Fluent selectors with the language's CLDR plural categories:

```
cpu-cores =
    { $count ->
        [one] { $count } core
       *[other] { $count } cores
    }
```

Fluent's Unicode isolation marks around arguments are off: the text renderer
would draw them.

## Adding a language

1. Copy a crate's `locale/en.ftl` to `data/locale/<lang>/<domain>.ftl` and
   translate the messages you want; leave out the rest.
2. Add `reprisekit.ftl` for the language with at least the two number
   separators.
3. Add `Name[<lang>]=` and `Comment[<lang>]=` to the program's
   `data/apps/*.desktop`.
4. Run `scripts/i18n-check`; it fails on an id that English does not have.
5. To try it without installing, copy the files to
   `~/.local/share/reprise/locale/<lang>/` and start the program with
   `LANGUAGE=<lang>`.

`data/locale/de/` holds a sample German translation of Notepad.

## Checks

`scripts/i18n-check` lists every `tr!` and `kit_tr!` id in the workspace and
fails when an id is missing from its crate's English `.ftl`, when an English
id is never used, or when a translation holds an id English does not.
`cargo test -p reprisekit` runs it (`tests/i18n.rs`), so CI does too.

Tests see English: under `cfg(test)` a crate's own domain ignores the locale.
reprisekit's strings follow the locale in other crates' tests, which matters
only with a reprisekit translation installed.

The plan, one crate per change, each ending with `scripts/i18n-check` green
and the pixel pins unchanged:

1. reprisekit's remaining controls (message boxes, property sheets, the
   shell views, the tray and taskbar parts), so every host inherits them.
2. The small programs: Volume, Date and Time, Drives, Power, Sound,
   Polkit, Accounts, Terminal.
3. The large ones: Explorer, Settings, Network, Printers, Bluetooth,
   Updates.
4. The compositor's `src/*view.rs` and its dialogs, then reprisefs's
   user-facing text (property sheet values, file type names) and the
   portal's dialogs.
5. The Start menu and launcher read `Name[xx]=` and `Comment[xx]=` from
   `.desktop` files; today they read only `Name=`.

Not covered yet: accelerator names in menus (`Ctrl+N` stays `Ctrl+N`), dates
and times beyond the 12/24-hour choice, and strings the config file
supplies.

Right-to-left languages are a later phase: mirroring layout rects in
reprisekit when the UI language is RTL, and `unicode-bidi` for the base
direction of mixed text. Shaping already goes through rustybuzz.
